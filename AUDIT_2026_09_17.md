### The five things that matter

1. **A `service_role` key for the live project sits in pushed git history** and was never rotated.
   It bypasses every RLS policy, which in this architecture is the entire authorization model.
2. **550 student Instagram handles are readable by anyone**, joinable to real name, school and
   class year, in one unauthenticated request. No public page uses the column.
3. **The whole 1,324-row member roster returns in a single GET**, 240KB in 1.5 seconds, with no
   pagination cap, no rate limit and no authentication.
4. **Soft-deleted posts are still served in full to anonymous callers.** The `deleted_at` filter
   exists only in client code.
5. **Every route the prerenderer does not cover serves the homepage canonical tag and no robots
   directive**, including 1,324 member profiles and 588 post permalinks. The safety design that
   `robots.txt` and the code comments describe does not exist in the bytes a crawler receives.

## 2. Method and evidence standard

**This pass had no database access.** No Supabase MCP connector, no SQL editor, no admin console.
`pg_policies`, `information_schema`, `list_migrations` and the advisors were all unavailable. The
only live data channel was the public PostgREST and Storage endpoints using the anon key, which is
exactly the channel a scraper has.

What that means for how to read this document:

- A finding says what an HTTP call **actually returned**. No finding asserts what a policy says.
- Anything needing the database to settle is marked `needs-db` and **capped at P2**, because its
  severity is unproven. Section 5 lists all of them with the query that would settle each.
- The applied status of all 148 files in `frontend/scripts/*.sql` is **deferred in full**.

Evidence actually collected:

| Probe | Scope |
|---|---|
| Anon read | 44 tables, per-column on `members`, exact row counts from `Content-Range` |
| Anon write | Zero-row-match `PATCH` and `DELETE` only. Nothing was created or modified. |
| Render | `design-probe.js` at 390, 1024 and 1280 on /, /members, /projects, /teams |
| HTTP | Status and header sweep over 28 routes, plus sitemap and robots |
| Build | Full production build at `8bc843d`, chunk table and `dist/` inspected |

### Two corrections to the audit method itself

Recorded so the next pass does not repeat them.

The planned non-destructive INSERT probe was **invalid**. Sending a deliberately invalid column name
returns `PGRST204` from the PostgREST schema cache *before* the request reaches Postgres, so every
table looked writable, including ones anon plainly cannot write. The result was discarded and
replaced with a zero-row-match `PATCH` and `DELETE`, which does discriminate and cannot mutate
anything. **INSERT permissions therefore remain unverified.** A zero-row match also proves only the
GRANT layer; RLS is never exercised when zero rows match.

The pre-pull seed catalogue was stale after 68 incoming commits, and was corrected before the audit
ran: 148 migrations not 124; **17** director desks not 18, with `approvals` now super-only; the `hr`
capability divergence **survived** the pull and moved to `capabilities.ts:207` and `:219`;
the `Companion` 500ms forced-layout loop **survived** its rewrite and now sits at line 438.

### What was not measured

The 17-tab HoD desk needs a logged-in session, so every desk finding is code-level and marked
`likely` at best. The live site was still serving the pre-pull build during probing, so SEO findings
distinguish "live does X" from "the code at 8bc843d does X".

#### [P1] SEO fix (a) "drop the hardcoded canonical at index.html:166" hard-fails the build  -  prerender-meta.mjs throws when that tag is absent

`frontend/scripts/prerender-meta.mjs:355`

The proposed fix reads: "(a) Drop the hardcoded canonical at index.html:166 (prerendered files inject their own...)". That premise is wrong about the mechanism. prerender-meta.mjs:355 is `html = replaceOnce(html, /<link rel="canonical"[^>]*>/, `<link rel="canonical" href="${esc(canonical)}" />`, 'link canonical')`, and replaceOnce at :319-324 is `if (!re.test(html)) { throw new Error(`prerender: could not find <head> tag to replace: ${name} (index.html layout changed?)`) }`. The prerenderer does NOT inject a canonical; it REPLACES index.html's. ## 8. Remediation plan

The sequence below is not the findings re-sorted by severity. It is ordered so that no step breaks a
later one, using the conflicts found in section 6. Two rules govern it:

- **Do not touch `db-max-rows` until track B has landed.** Two findings give conflicting values for
  that one global setting, and the lower value silently truncates at least eleven live queries.
- **Do not prerender `/member/:uuid`.** The SEO case for it is real, and it directly undoes three
  anti-scraping findings by publishing a static, key-free, crawlable name index of 1,324 minors to
  the CDN. If the two goals ever have to be reconciled, the roster exposure decision (track D) comes
  first.

Highest value per unit of risk. Every item here is a revoke or a one-line change, needs no migration
ordering, and breaks nothing.

### Decisions only you can make

1. **The roster.** 1,324 mostly-minor students are enumerable by name, school and class year in one
   unauthenticated request. A public community directory is *supposed* to be visible, so this is a
   product judgement, not a bug. The options, cheapest first: revoke the gratuitous columns only
   (track A, already recommended); also drop `class_grade`, which no public surface renders per
   member; add a server-side page-size cap; drop `count=exact` to break deterministic paging; put an
   Edge Function in front of the data. Note that `robots.txt` and `vercel.json` headers do **nothing**
   here, because the browser calls `*.supabase.co` directly and the Vercel edge is not in that path.
2. **PII already in git history.** ~2,360 member emails and phones are in pushed history at `72c28f5`,
   separately from the `service_role` key. Rotation does not touch that. Purging means a history
   rewrite and a GitHub Support ticket for unreachable blobs.
3. **The soft 404.** Every unknown path returns 200 with the homepage. The audit recommends **against**
   Edge Middleware here: on a 619-URL site the drift risk costs more than the crawl budget does.
4. **The "for you" feed.** Page 1 runs four bucket queries plus a 60 to 100 row pool fetch on the home
   page critical path. Your 2026-09-12 call was "always sorted by latest", but that was made against a
   three-bucket version; upstream has since added a fourth bucket fed by the new follows feature.
   Section 4.5 has the performance case; the product call is yours.
5. **`hr` versus `super_admin`.** `lib/roles.ts` says they are equal in power. The capability engine
   disagrees in three places. Deciding which is right determines whether A5 is a fix or a policy change.
