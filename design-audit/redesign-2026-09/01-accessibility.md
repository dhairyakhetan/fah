# 01 — Accessibility audit

**Scope** `frontend/src/**` excluding `frontend/src/paradox/**`.
**Date** 2026-09-03. **Method** static read of every `.tsx`/`.css` in scope plus
computed contrast ratios (sRGB relative luminance, WCAG 2.x formula). No browser
run — every row marked `Not verified` at the bottom is one I could not confirm
without a live page.
**Constraints honoured** `REDESIGN_GUARDRAILS.md`: no Supabase query, `.from()`,
column or RLS change is proposed anywhere below. UX, copy, fonts and hues are
unchanged — every colour fix swaps a *display hue used as text* for the `*-ink`
variant that `styles/tokens.css` already defines for exactly that purpose. No em
dashes were introduced into user-facing copy.

**This is an audit. No file was edited.**

---

## How to read this

| Grade | Meaning |
|---|---|
| **P0** | Blocks a task outright, or hides content from assistive technology. A keyboard-only or screen-reader user cannot complete the flow. |
| **P1** | Makes an interaction meaningfully harder, or fails a WCAG AA success criterion that carries real user cost. |
| **P2** | Isolated polish, or a criterion that fails by a small margin. |

Locations are given by **file path + selector or quoted string**, never by line
number. Fixes are written to be applied without design judgement: where a value
is needed, the value is given.

## What is already right

Worth stating so nobody "fixes" it:

- `hooks/useDialog.ts` is a single, correct, shared implementation of Escape,
  Tab trap, focus-restore and body scroll-lock. Ten dialogs use it. The fixes
  below are almost all "route this dialog through the hook that already exists."
- `components/Tabs.tsx` is a correct WAI-ARIA tablist with roving tabindex and
  Arrow/Home/End keys. `components/Toggle.tsx` is a correct `role="switch"`.
- `styles/v6.css` `@media (max-width: 760px)` block sets `min-height: 44px;
  min-width: 44px` on `.btn, .chip, .rail-cat-tile, .rail-launcher-tile,
  .aq-tab-item, .aq-nav-icon-btn, .aq-hamburger, .aq-post-action, .post-act`.
- `styles/v6.css` has a global `prefers-reduced-motion: reduce` catch-all, and
  every `framer-motion` component reads `useReducedMotion()`.
- `.aq-footer-link` at `rgba(255,255,255,0.62)` on `#0A0A0A` measures 7.76:1.
  `styles/footer.css` carries a comment recording the previous failure. Leave it.
- Every `<img>` in scope has an `alt`. `.sr-only` in `index.css` uses the
  correct clip-path technique. `<html lang="en">` is set. No positive `tabindex`
  anywhere. Every `target="_blank"` carries `rel="noopener noreferrer"`.
- `components/Confirm.tsx` is a correct `role="alertdialog"` with a Tab trap,
  Escape, and Cancel autofocus.

# D. The HoD desk — `director/`, `styles/routes/director*.css`

Three structural questions were asked of this desk and answered by reading the code. Recording the answers here so nobody re-opens them:

**The 17 desk "tabs" are not a tab widget and must not become one.** `DirectorDashboard.tsx` renders them as `react-router` `<NavLink>` route links, twice: `navList('strip')` inside `<nav className="ops-navstrip" aria-label="Director sections">` and `navList('sidebar')` inside `<aside className="ops-sidebar" aria-label="Director sections">`. Active state comes from NavLink's own `aria-current="page"`. Only one of the two is in the accessibility tree at a time (`.ops-sidebar { display: none }` below 1024px, `.ops-navstrip { display: none }` at 1025px and up), so there is no duplicate-link problem either. **Do not add `role="tablist"`.** The real defect there is D6. By contrast `ProjectModal.tsx`'s four in-modal panel switchers *are* a genuine tab widget with no tab semantics at all — that is D24.

**`hooks/useDialog.ts` (`useModalA11y`, re-exported from `adminKit.tsx`) is correct and complete** — Escape suppressed while busy, a Tab trap re-queried on each keypress, focus-in on open, focus restore on close, body scroll-lock restoring the previous value. Nine desk dialogs call it. Two surfaces skip it entirely (A25 and D19).

**Almost every `outline: none` in the desk already has a replacement in the same file** and is not a finding: `director.css`'s `.adm-search input` is covered by `.admin .adm-search:focus-within { border-color: var(--ink); box-shadow: var(--hod-shadow); }`; `.admin .input:focus, .admin .textarea:focus, .admin select:focus` sets its `box-shadow` ring in the same rule; and `director-people.css`'s `.admin .mdir-select` and `.admin .adm-sort select` are real `<select>`s picked up by that same `.admin select:focus` ring. The single genuinely unreplaced one is A26.

**What was NOT done — report every one of these as `Not verified`:**

# G. Verdict

**Block.** Twenty-two P0 findings remain: A1 through A10, B1 through B5, C1 through C3, and D1 through D6. Each one either prevents a task outright for a keyboard-only user or hides content from assistive technology. Notable among them, because they sit on the app's busiest surfaces: no post can be opened from the feed by keyboard (C1), no notification row is reachable (C2), the mobile navigation drawer is a focus trap in the wrong direction (A2), and no project can be published or featured from the HoD desk without a mouse (D1).

The rest of this document is the work list. It should be read alongside the fact that this codebase already holds itself to most of this standard — `hooks/useDialog.ts`, `components/Tabs.tsx`, `components/Toggle.tsx`, `components/Field.tsx`, `adminKit.tsx`'s row primitives and the `*-ink` token family are all correct implementations that simply have not been applied everywhere. Almost every fix above is "use the thing this repo already built," not "build something new."
