# Closing audit — 2026-09-11

Visual, technical, responsive, interactive and workflow. This is the closing
deliverable asked for on 2026-09-10 ("end with a complete visual technical
responsive interactive workflow audit of every page function component section
fold task"), run after the session's work rather than as an interim report.
It supersedes `AUDIT_2026_09_10.md`, which is kept for its incident history.

**How this was run.** A DOM probe driven in a real browser at 375 and 1280,
measuring horizontal overflow (and whether the page can actually scroll
sideways), control size against the 44px floor, accessible name on every
control, heading structure, and images without `alt`. Database behaviour was
verified by **simulating real signed-in sessions inside rolled-back
transactions** (`set local role authenticated` + a real `auth_uid` in
`request.jwt.claims`), not by reading policy text. Plus the four repo gates and
both Supabase advisors.

**What this audit is not.** Signed-in *data* pages were exercised through the
`?dev=` preview, which fakes a role client-side **with no Supabase session**.
Those pages render their empty or permission-denied states, so their layout is
audited and their data is not. Anything needing a real browser session is
marked NOT VERIFIED rather than passed.

## Test data

Wiped and verified, not assumed. `sim_seed_registry` is empty, and a sweep of
**every `text`/`varchar` column in every base table** for `[SIM]` returns zero
rows:

```sql
select table_name, column_name, cnt from (
  select c.table_name, c.column_name,
   (xpath('/row/c/text()', query_to_xml(format(
      'select count(*) as c from public.%I where %I like ''%%[SIM]%%''',
      c.table_name, c.column_name), false, true, '')))[1]::text::int as cnt
  from information_schema.columns c
  join information_schema.tables t
    on t.table_name = c.table_name and t.table_schema='public'
   and t.table_type='BASE TABLE'
  where c.table_schema='public' and c.data_type in ('text','character varying')
) s where cnt > 0;
-- 0 rows
```

`sim_seed_registry` and `sim_seed_teardown()` are KEPT, empty. They are the
mechanism that made the seeding reversible; deleting them would only make the
next round of seeding unreversible.

## Fixed during this audit

**Six tap targets under the floor.** The previous audit reported "0 controls
under the 44px floor". Probing the signed-in feed and the public forms found
six, all now fixed and re-measured:

| Control | Before | After |
|---|---|---|
| Feed engagement row (like/comment/save/share/more) | 40px tall | **44** tall, 40 wide |
| `.aq-field-input` (contact + collaboration forms) | 286×36 | **286×47** |
| `.aq-logo` (every page) | 40×40 | **44×44** |
| `.skip-to-main` (first keyboard stop) | 211×40 | **211×44** |
| Feed card author button | 306×36 | **306×44** |
| Home composer icon buttons | 40×44 | **44×44** |

The feed one is worth spelling out. Its 40px floor is *documented as a
deliberate trade*, with a comment warning against "fixing" it. Reading it
closely, the stated reason is **horizontal** — "5×44 plus gaps overflows a
375px card" — and `min-height` cannot cause horizontal overflow. The height
was collateral. Raising only the height left the row's `scrollWidth` at 322
before and after. The width half of the trade is untouched and still documented.

The logo also demonstrated the failure mode its own comment warned about:
raising the base rule produced **40×44**, because a mobile override still held
`min-width: 40px !important`. Caught by re-measuring rather than assuming the
change had taken.

**Every desk tab now has an `h1`** — finding F1, open since the last audit.
`AdminTabHeader` rendered the title as `h2`, so all 17 `/director/*` routes
reported `h1: 0` and started their outline at level 2. Promoted in the one
shared component; `.adm-header-title` is class-scoped, so nothing moved.

**The desk printed the same sentence twice.** On an empty desk, the triage
card's "nothing waiting across every category - nice work" appeared at y=296
and the jigsaw's clear block repeated it verbatim at y=510. Two reasonable
decisions from different spec sections producing an unreasonable result.

**Two functions I created were callable by `anon`.** Found by the security
advisor. `revoke all on function ... from anon` does not do what it appears to:
Postgres grants EXECUTE to PUBLIC by default and `anon` inherits it, so
revoking by name removes a grant that was never held individually. Both
`role_can` and `mom_target_is_active_member` carried `=X/postgres`.
`mom_target_is_active_member(member_id)` was the one that mattered — an
unauthenticated caller could have enumerated which member ids are active.
Revoked from PUBLIC; verified `anon` now gets 42501 and `authenticated` still
works.

**Achievements were completely broken.** Not cosmetically — the database
refused the write with 42501, every time, for every non-director. On
2026-09-03 achievements were changed to go live on submit (review desk
deleted, column default moved to `'approved'`, service changed to send
`status: 'approved'`), and the RLS INSERT policy was not changed with them: it
still demanded `status = 'pending'`, the one value nothing writes any more.
`external_achievements` holds 3 rows live, which fits a feature that has been
dead since that day.

**The role guard was lying.** An unauthorised role change was answered with
`new.role := old.role` — a silent revert. `ROW_COUNT` came back 1, PostgREST
returned the row, `error` was null, and all three role writers selected back
only `member_id`. The desk would have toasted "promoted to HoD" over a database
that did nothing. It now raises 42501, and the app reads the role back and
throws if it is not what was asked for.

## Still open, and why

### Blocked on a decision, not on code

- **4.2 Blog Drafts / merge blogs into posts.** `blogs` is a separate table
  with 36 real rows and its own publish-mirror trigger. Migrate-into-posts vs
  just removing the desk is a data decision.
- **3.1 Directory "archive".** There is no archived or alumni state in the
  schema: `members.status` is only `active` (1,317), `pending_approval` (58),
  `rejected` (4). An archive needs a definition before it can have a UI.
- **5.8 role changes.** Parked by the user.

### Built and correct, but scoping nobody today

**6.1 / 6.2.** Hiring and the Post Queue are both scoped, and the mechanism is
tested. It narrows nobody live, because **every team lead in the database is
either a super_admin (unscoped by rule) or role `member` (cannot reach the
desk)**. The single `hod` leads no team and has no category assignment, so the
fail-open rule leaves them unscoped — deliberately, because an emptied desk
looks exactly like "nobody applied". This starts working the moment someone is
given a lead row or a category. That is an ops action, not a code change.

Likewise all 20 `director_categories` rows belong to super admins, so category
moderation scopes nobody either.

### Real, and not fixed

- **3.2 project card variations, 5.1 members auto-hydrate, 5.6 team detail
  fields, 7.4 SOPs across people, 7.7 Projects/People overlap, 8.2 live
  updates.** Not started. 8.2 in particular is ambiguous enough ("saves,
  profile, searches should update dynamically") that building it on a guess
  risked the wrong thing; realtime already exists in three places (`AQNav`,
  `BirthdayPopup`, `VolunteerApplications`) so the pattern is there when the
  scope is pinned down.
- **The nav bar is now mixed type.** Item 1.1 converted the drawer and the
  dropdown to NeutralFace caps. The top-level `.aq-nav-link` bar is still
  lowercase Eina, because changelog 02.4 specifies that explicitly and says the
  bar was *drawn* lowercase. Converting it too is a one-line change and the
  owner's call.
- **`.aq-nav-link` is 40px tall at desktop.** That is 02.4's specified value
  and clears WCAG 2.5.8 AA. Left alone rather than overriding an approved spec.
- **`/profile/me` and `/yearbook` report `h1: 0`.** NOT VERIFIED: both render
  "profile not found" under `?dev=`, which has no Supabase session, so the real
  page was never on screen.

### Accepted, recorded so they are not "fixed" later

- **Text links under 44px**: anchors wrapping headings (215×26, 284×30) and
  inline `.link-cta` / `.aq-thread-link` (92×24, 105×24, 207×24). They are
  text, they meet WCAG 2.5.8 AA's 24px, and padding them to 44 would wreck the
  typography around them.
- **Feed engagement buttons at 40px WIDE.** The documented horizontal trade.
- **40 unused indexes** (perf advisor, INFO). Every one is on an empty or
  near-empty table. An index on an empty table is never used; this is not a
  finding.

## Three false alarms, recorded so nobody chases them

**The console is not full of errors.** A fresh-tab load of `/` appeared to show
six 400/401/406 failures. `aq_dev_preview_role=super_admin` was still in
`localStorage` — same origin, so a new tab inherits it — and the app was
issuing queries for the fake member id 999999. After clearing storage, **all 7
Supabase calls on an anonymous load return 200/206**. The console reader also
accumulates across navigations, so the six lines were stale. This is the second
time this trap has been hit in this project; the reliable test is
`performance.getEntriesByType('resource')` with `responseStatus`, on a page
loaded with storage cleared.

**`permission denied for table members` was not a regression.** While testing
the role guard, a control case failed with that error. It was the test's own
`WHERE` clause reading `auth_uid`, a column `authenticated` has no SELECT grant
on under the PII lockdown; the grant error is thrown before any trigger runs.
`authenticated` does hold column-level UPDATE on `role` and `status` — the
trigger, not the grant, is what gates them.

**Follow mode was not broken.** A companion test appeared to show the follow
flag not activating from `localStorage`. The flag is `sessionStorage`, by
design — follow mode is session-only. The test was wrong, not the app.

And from the previous audit, still true: **`/director/roles` does not overflow**
at 375. Re-confirmed at 1280 across all six desk routes probed.

### The eleven walkthroughs

Every flow driven start to finish. **8 of 11 were broken; all 11 now reach
their end card.** Three real bugs, one of them mine:

| | |
|---|---|
| post-to-feed | 4/4 | apply-for-role | 5/5 |
| sign-up-drive | 3/3 | search-discovery | 3/3 |
| wall-note | 3/3 | request-certificate | 3/3 |
| generate-cv | 3/3 | take-a-break | 3/3 |
| hod-approve-account | 3/3 | hod-moderate-post | 3/3 |
| hod-post-opening | 4/4 | | |

1. **The coach loop ran on `requestAnimationFrame` alone.** rAF is not a clock.
   In any surface the browser stops painting, the step never completes *and*
   the lost-target safety net never fires either, because it counted frames.
   Frozen spotlight, no error, no way forward. Now two drivers plus a
   millisecond grace period.
2. **`nextFrame()` resolved inside rAF**, so `doItForMe` hung forever in the
   same conditions - button stuck on "doing it…". Now raced against a timer.
3. **My own regression from earlier the same day.** The capability engine put
   `useCan()` gates into the desk screens. `CapabilityProvider` is mounted
   above the router, so inside a demo it is an ancestor of `DemoProvider` and
   read the real signed-out auth: every capability false. The HoD approval
   flow rendered `view only` where the approve button belongs. All three HoD
   flows were dead. `DemoProvider` now nests its own provider inside the fake
   auth.

**Links:** all 11 resolve at `/demo/<id>`, all distinct, none inert. The
launcher shows 3 with the rest behind "all 11 walkthroughs" - deliberate.

**Sandbox:** zero supabase / rest / realtime requests during a full HoD flow.

**Durability:** `demo/flows/selectors.test.ts` extracts every class hook the
flows depend on *from their own source* and asserts each still exists in the
product. Proven with a negative control - renaming `cp-chiprow` turns it red
naming the flow, the selector and the consequence.
