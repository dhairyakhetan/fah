# /member/ is deliberately CRAWLABLE for search engines, for exactly the reason
# /post/ is (spelled out below) — and every /member/:uuid now carries
# robots=noindex (see src/profile/PublicProfilePage.tsx). Disallow prevents
# crawling, not indexing: a profile linked from an Instagram bio or a WhatsApp
# group can still be indexed as a bare URL, and a URL Google may not fetch is
# one whose own noindex it can never read. Allowing the crawl is what lets the
# STRONGER exclusion apply. These are real students, many of them minors, so
# the stronger exclusion is the one we want.
# The AI-crawler groups below deliberately KEEP /member/ disallowed — training
# data is a separate question from indexing.

# /post/ is deliberately CRAWLABLE for search engines, and that is not an
# oversight. These are permalinks - they get shared into WhatsApp, Instagram
# and group chats, so they pick up external links whether we like it or not.
# A robots-disallowed URL that is linked externally can still be indexed as a
# bare URL, and because it is never fetched, Google never sees the page's own
# instructions. Allowing the crawl is what lets those instructions apply:
#   - mirrored posts (blog/project/opening -> post) carry rel=canonical to
#     their real home, so ranking signal consolidates there instead of being
#     split across 555 duplicate URLs;
#   - member-authored posts carry robots=noindex, which is a STRONGER
#     exclusion than Disallow, not a weaker one.
# The AI-crawler blocks below deliberately KEEP /post/ disallowed - that is
# about training data, which is a separate question from indexing.
# See the canonical/indexation block in src/feed/PostPage.tsx.
